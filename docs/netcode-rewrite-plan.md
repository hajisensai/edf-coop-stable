# EDF6 联机重写计划（netcode rewrite）

2026-10-06 立项。目标：接管 EDF6 原版联机同步，提升联机速度和体验，消除「玩家行为和目标在不同玩家那里显示不一样」，同时兼容 [edf6-all-forces](https://github.com/hajisensai/edf6-all-forces)（EDF6VehicleCrew.dll）。用户已授权：**游戏规则可以改**（例如命中判定权威）。

## 1. 现状（已核实的事实）

- 原版联机没有房主权威，**每个对象只归一台机器管**。网络对象的 `+0x128` 标志：bit0 表示归其它机器，bit1 表示归本机（all-forces `docs/online-re.md` §2-3）。
- 远端副本在本机照样跑完整物理，只靠收到的位姿软拉修正，**不外推，包里也不带速度**。玩家每 90ms 发一次，每次只修正误差的 5%（`multislot/src/smoothing.h:15-24`）。
- **命中在被打的那台机器上判定**，所以「我看到打中了，对方那边没中」。
- 任务脚本和空袭在每台机器上各自确定性地跑一遍，靠同一个种子保持一致（online-re §1）。
- 两层传输：
  - 上层是游戏自己的包控制器（`12CB5F0`，90ms 定时），负责 AES-CTR 加密、去重、确认和重发。
  - 下层是 EOS，原版用不可靠发送。coop 现在把它改成了可靠发送（`src/eos_hooks.cpp:1748-1757`），等于两层可靠叠在一起。
  - 直连是星型拓扑，客人之间的包都经房主中转。
- all-forces 自定义的对象（呼叫飞机、无人机、生物、AutoCrew 放的 NPC 驾驶员、直升机飞控）**都没有网络身份**，每台机器各算各的。AutoCrew 在客人机器上也会安排 NPC 上车，于是那台机器自认是这辆车的权威（`src/crew.cpp` 里没有任何「是否在联机」的判断）。

## 2. 总原则

1. **协议版本门**：改了规则就要求全员同一版本。房主公布 netcode 版本和能力位（沿用 syncmarker 的成员标记机制），版本不一致的成员不启用新协议。启用新协议的房间，房主拒绝不兼容的成员，并给出明确提示，不能静默不同步。
2. **逐类接管，不一次推翻**：每一类对象（玩家 / 命中 / 敌人 / 子弹 / 任务事件 / 插件对象）单独有开关，默认开启，出问题可以单独关回原版行为。
3. **测试**：
   - 能在 `tests/gamenet` 无头测试里验证的，必须加场景。
   - 只能真机验证的，在 PR 里标「待真机验证」，不宣称已修好。
4. **补丁纪律**：先核对原字节；两个插件（coop 与 all-forces）不能补丁同一个 RVA；只认当前这一个 EDF.dll 版本（TimeDateStamp `0x678CCB46`）。

## 3. 工作流

| 编号 | 仓库 / 分支 | 内容 | 验证 |
|---|---|---|---|
| W1 网络层 | coop `feat/net-transport` | P0：按消息类型和对象类型统计流量（频率、字节数、间隔），写进 traffic 日志。P1：① 去掉双层可靠，状态类包改回不可靠、只保留最新一份，事件类包保持可靠；② 直连改成网状拓扑，客人之间直连，打洞失败才经房主中转；③ 把开局同步专用的拆包推广成通用的分片和重组；④ 查清 XPRESS 压缩为什么被撤回，再决定要不要重新上；⑤ 协议版本门（§2.1） | gamenet 新场景：丢包、延迟、网状直连、分片、版本不一致 |
| W2 玩家同步 | coop `feat/net-player` | P2：逆向玩家角色（SoldierBase）的复制写入、读取和发送节流；包里加速度和时间戳，远端按速度外推并做误差收敛（替换 5% 软拉）；提高玩家位姿的发送频率 | gamenet：序列化往返、外推数学的单元测试；手感待真机 |
| W3 命中权威 | coop `feat/net-hit-authority` | P3（改规则）：命中由开枪的人判定，伤害消息发给目标的拥有者执行，拥有者只做合法性校验（距离、射速上限）；覆盖玩家打敌人、敌人打玩家、友伤 | gamenet：伤害消息往返和校验；实战待真机 |
| W4 敌人 / 子弹 / 任务事件 | coop `feat/net-world` | P4：逆向敌人注册族 `0x781630`、敌人状态复制与 AI 拥有者、NetworkBullet、任务脚本注册族 `0x7834F0`、随机数来源；把敌人 AI 和 HP 收归房主权威（或定期由房主校正），任务关键事件（波次、敌人生成、死亡）由房主广播确认 | 逆向文档 + gamenet 能覆盖的消息往返；实战待真机 |
| W5 all-forces 联机一致 | all-forces `feat/online-authority` | AutoCrew 与插件直升机飞控只在载具权威（或房主）那台机器跑；插件伤害（撞击、钻头、EMC）只在权威机器结算；呼叫飞机由呼叫选择 + 种子同步保证全员一致，或改为房主生成并注册网络身份；所有改动都要有联机门 | 单元测试 + 源码守卫；两机实测待真机 |

各工作流分支都基于 `feat/netcode-rewrite`，最后合进集成分支，审查后再开 PR 合进 `main`。

## 4. 影响范围与风险

- 与 all-forces 共存：W2-W4 新增的 hook 要列出 RVA 清单，和 all-forces 的补丁地址比对，不能重叠。
- W3、W4 改变游戏规则。没装新版本的成员无法加入启用了新协议的房间。
- 原版 EDF.dll 一旦更新，所有 RVA 都要重新确认。各模块启动时先核对字节，对不上就不启用、只写日志，不会崩。
- 真机验证缺口：手感、实战命中、敌人一致性只能真机确认，在 PR 里逐条列出。
