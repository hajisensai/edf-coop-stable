# PR #25: voice HUD record allocation

Reviewed `a5616364033574f52ca66689b1b21dc90ffc16c3` against the supported
EDF.dll (timestamp `0x678CCB46`). No additional production defect was found.

The constructor's allocation at `9606AE` receives the patched constant
`0x50 * 1024` bytes. The complete `961930` destructor computes its byte size
from the capacity, takes the large-allocation branch at `961A25`, reads the
original address at `[buffer - 8]`, and requires an offset of 8 through 39
bytes before calling the game's delete at `12D85EC`. Allocating 39 extra
bytes and rounding `(block + 39)` down to 32 bytes meets that contract.
The fixed constructor size cannot overflow the size or alignment arithmetic.
The game's allocator is assigned before the checked call redirection is
installed; the redirection and size patches share the existing rollback path.

The original test compares the code signatures and reproduces the free
predicate in C++. The review adds a stronger regression to `load_test.cpp`:
load the real plugin against a private `DONT_RESOLVE_DLL_REFERENCES` mapping,
follow its installed allocation-call thunk, construct records using the
game's `9621A0`, then execute the complete `961930` destructor. It covers
4, 52 and 1024 records, three lifetimes each, and destruction of the cleared
vector. This runs in every enabled load-test mode, including `nomission`;
disabled mode checks that the original allocation call remains intact.
Only the test process's CRT imports are resolved. No game process, game
initialization or installed mod files are involved.

Validation at `05c4671`: MSVC x64 release build with real game assets (no placeholders),
`build.ps1 -Test` at `-j3`, 81/81 CTest cases passed without skips. The native

`PluginLoad_host4` fail fast with `0xC0000409`; the mutation was then removed,
the production DLL rebuilt, and all 11 patch-table/plugin-load cases passed

This is not a live mission-end or multiplayer playtest. The multi-process
GameNet tests use their existing fake EOS transport and private game mappings.

The next analysis flagged backward backlink reads/writes whose allocation
extent was not expressed at the call site. The final layout computes a
0..31-byte padding from the allocation address remainder, writes the backlink
at that non-negative offset from the original block, and returns the following
payload. No alignment API failure path is needed: the arithmetic guarantees
an 8..39-byte prefix and avoids adding to the integer representation of the
address. The test reader now takes the full allocation span and a checked
payload offset. Regression coverage exercises all 32 base-address remainders
and rejects missing prefixes/out-of-range payloads before reading metadata.
The affected MSVC build and all 14 native/unit/load cases passed again.
