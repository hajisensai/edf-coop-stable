# 健康直连被原版超时维护踢出（2026-10-11）

双方日志 #11：20:34:06 支援传输已就绪。20:35:13.848 房主收到 EOS TimedOut，
插件保留事件，因为已认证直连仍活着；20:35:13.864 游戏却调用 KickMember，随后客户端离房，支援会话暂停。
原处理只暂缓 EOS 断连回调，但没有阻止原版房间维护独立发出的自动踢人请求。
后续重连及任务包切换时不能用“菜单里十秒没收到游戏数据”作为真人离开的证据：直连心跳仍可验证连接。

本次在原生失败连接消费源处保留满足全部条件的连接：

- 支持的 EDF.dll 维护调用 12C04C0 及其后消费指令完整匹配，在失败列表进入踢人/离房分支前检查；
- 目标仍是当前房间成员；
- 该目标当前确有被插件暂缓的 EOS 超时；
- 同一认证直连仍健康。

手动踢人（原生 UI 调用 8F6C55）、房间关闭/清理、未知调用、真实断线或已离开的成员不被保留。
不重新建立虚构用户，不跳过身份认证，不删除已创建支援对象。检查前锁定真实 User 的弱引用，
过滤时释放原失败列表持有的弱引用，最后释放临时强引用；失效弱引用不读取其对象。
日志新增 `native closed-peer list: retained`，供两端复测确认实际路径。

离线验证包含全部四条件的 16 种组合； native 调用与回调均已只读反汇编核对。
