# EDF6MultiSlot 1.5.14

## English

- **8+ player missions start again:** the mission start message grew past EOS's 1170-byte packet limit at eight players (1180 bytes), so the host resent it for ~26 s and then dropped everyone. Loadout records that don't fit now travel beside it as separate packets; smaller rooms send exactly what they did before. Everyone in a room of more than four needs this version. With `NetLog=1`, any other game packet over 1170 bytes is now logged once, with its sender.
- **Whole room left when a newcomer could not connect:** when the P2P handshake with someone never completed, the game made every member except the host leave the room 20 s after they joined (`788ABF`: not the host and any link timed out → leave), however long the members had been playing there. Now a member who had finished its own join before the newcomer came stays, and the newcomer stays unconnected until their own game gives up and leaves (the host already behaved like this); someone whose own join fails still leaves. `[MultiSlot] KeepRoomOnPeerTimeout=1` (default; 0 = the game's behaviour). The timeout, which the game re-checks every frame, is now logged once per link instead of about 500 times a second.
- **Crash after refusing to load (1.5.13 regression):** with `Enabled=0`, or when a game update or another mod made the plugin back out without changing anything, the game crashed about 0.2 s later: the log writer thread outlived the unloaded DLL. The writer now starts only once the plugin stays loaded, and an unload is logged as `UNLOADED`, not `SHUTDOWN`.
- **Rooms above this build's size:** the member list is cut to the build's player count, so a larger room (another mod, or a hostile host) can no longer crash everyone.
- **Log survives a hard kill:** lines are queued in a memory-mapped `EDF6MultiSlot.log.queue` that the next start replays, so a task-manager kill or `__fastfail` no longer loses the last lines. Member names can no longer forge log lines, and long CJK names are no longer shown as `(no name)`.
- **Copy armor:** the pickup count is computed in at most 24 steps and absurd values reported by other members are ignored, so they can no longer freeze the game.
- **Crash reports:** thunks and call stubs register unwind data (stack walks and exceptions pass through hooks), the plugin's own guarded probes no longer count as crashes, and faults inside the plugin get a dump too.
- **CI:** `.github/workflows/multislot.yml` builds 8/10/12 and runs every test that does not need the game (`-DMULTISLOT_CI=ON`, a marked placeholder layout that `package.ps1` refuses to package).

## 中文

- **8 人以上又能出击了：** 出击同步消息在 8 人时变成 1180 字节，超过了 EOS 单包 1170 字节的上限，房主重发约 26 秒后把所有人踢出。现在放不下的装备记录会用单独的包另行发送，人数少的房间发出的内容与以前完全相同。5 人以上的房间里所有人都需要这个版本。`NetLog=1` 时，其他超过 1170 字节的游戏包会记录一次，并注明发送位置。
- **新人连不上时整个房间的人都退出：** 与某人的 P2P 握手一直没完成时，游戏会在他加入 20 秒后让除房主外的所有成员退出房间（`788ABF`：不是房主且有任一连接超时 → 退出），不管成员已经在里面玩了多久。现在，在新人来之前已经完成自己加入的成员会留下，新人在这边保持未连接，直到他自己的游戏放弃并退出（房主本来就是这样）；自己加入失败的人仍然会退出。`[MultiSlot] KeepRoomOnPeerTimeout=1`（默认；0 = 游戏原本的行为）。游戏每帧都会重新检查这个超时，现在每个连接只记一行日志，而不是每秒约 500 行。
- **拒绝加载后崩溃（1.5.13 回归）：** `Enabled=0`，或因游戏更新、其他 MOD 冲突而插件什么都不改就退出时，约 0.2 秒后游戏崩溃——写日志的线程活得比已卸载的 DLL 还久。现在只有插件确定留下后才启动写线程，卸载记为 `UNLOADED` 而不是 `SHUTDOWN`。
- **超过本版人数的房间：** 成员列表截断到本版人数，更大的房间（其他 MOD 或恶意房主）不再能让所有人一起崩溃。
- **强制结束也不丢日志：** 日志行先写进内存映射的 `EDF6MultiSlot.log.queue`，下次启动补回，任务管理器结束或 `__fastfail` 不再丢最后几行。成员名不能再伪造日志行，长的中日文名字不再显示成 `(no name)`。
- **复制护甲：** 拾取次数最多 24 步算出，其他成员报出的离谱数值会被忽略，不再能让游戏卡死。
- **崩溃报告：** 跳板和调用桩注册了 unwind 信息（栈回溯和异常能穿过 hook），插件自己受保护的探测不再算作崩溃，插件内部的故障也会写 dump。
- **CI：** `.github/workflows/multislot.yml` 构建 8/10/12 人版，跑所有不需要游戏的测试（`-DMULTISLOT_CI=ON`，使用带标记的占位布局，`package.ps1` 会拒绝打包）。

## 日本語

・8人以上でも出撃できるようにしました：出撃時の同期データが8人で1180バイトになり、EOS の上限（1170バイト）を超えていたため、
  ホストが約26秒再送したあと全員が切断されていました。入りきらない装備情報は別のパケットで送るようにしました。
  人数の少ない部屋の送信内容はこれまでと同じです。5人以上の部屋では全員がこの版にそろえてください。
・接続できない人が入ってくると、ホスト以外の全員が部屋から抜けてしまう問題を直しました。
  参加した人との P2P 接続（参加確認）が 20 秒たっても終わらないと、ゲームはどれだけ前から
  遊んでいたメンバーでも部屋から抜けさせていました。今は、その人が来る前に参加を終えていた
  メンバーは部屋に残り、つながらない人はその人自身のゲームがあきらめて抜けるまで未接続のままです
  （ホストは元からこの動きです）。自分の参加が失敗した人は、これまでどおり抜けます。
  元の動きに戻すには、EDF6MultiSlot.ini の [MultiSlot] に KeepRoomOnPeerTimeout=0 を書いて再起動します。
・起動直後に落ちる問題を直しました。Enabled=0 のとき、ゲームの更新や他の MOD と合わず
  プラグインが何も変えずに身を引くとき、約 0.2 秒後にゲームごと落ちていました（1.5.13 の不具合）。
  ログを書くスレッドは、プラグインが残ると決まってから動くようにしました。
・8人（10人版・12人版はその人数）を超える部屋に入ったとき、全員が落ちないように
  メンバー一覧をその人数までに切り詰めます。
・ログ：強制終了（タスクマネージャーでの終了など）でも最後の行が失われないようにしました
  （プラグインのフォルダーに EDF6MultiSlot.log.queue ができます。消しても大丈夫です）。
  他の人の名前に改行などを入れて、ログの行を偽装することはできなくなりました。
  長い日本語の名前が「(no name)」になっていたのを直しました。
・アーマーのコピー：他の人が極端な値を出していても、画面が固まらないようにしました。
・落ちたときの記録：プラグイン自身の中で起きた異常も記録し、プラグインが安全に確かめている
  処理を「落ちた」と誤って記録しないようにしました。
・部屋の仕組みは変えていません。1.5.5 以降の人とも互いに部屋が見え、参加できます。
