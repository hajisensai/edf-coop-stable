# EDF6MultiSlot 1.5.15

## English

- **A split start message only goes to players who can read it:** since 1.5.14, a host of 8+ players replaces the loadout records that don't fit in the start message with a short stub and sends the record beside it. A machine without that change reads the stub as a number and every later record out of line, and the bad player index it ends up with is written into memory unchecked. Some packages built on 2026-09-30 call themselves 1.5.14 but don't have the split, and every MultiSlot version shares the same rooms, so neither the version nor the room can tell them apart. So each player now publishes a marker on their own lobby entry, which the game never reads. The host sends a split start message (and the records beside it) only to members it has seen with that marker. A member without the marker gets what EOS answered before 1.5.14 (the message is not sent), and the log names them once per room. **Everyone in a room of 8 or more needs 1.5.15 to start a mission**, including players on the 2026-10-01 pack.
- **No wait for a resend when the start message arrives first:** the records beside the start message travel as separate packets, and reliable delivery keeps no order between them, so the message can arrive before its records. It used to be dropped, which cost the game a resend about three seconds later. Now it is held, and handed to the game as soon as its records are in, still from its sender on its socket and channel. At most 8 messages are held (the oldest is dropped first), each for at most 30 s, which is longer than the game keeps trying. Leaving the room clears them.
- **Lighter packet scan:** every game packet sent or received is searched for stubs. The search now jumps from one candidate byte to the next instead of trying every position.
- **Logs:** `MISSION sync:` lines say when our marker is published, which member cannot read a split message, and when a held message is handed on or dropped.

## 中文

- **拆分后的出击消息只发给能读懂的人：** 从 1.5.14 开始，8 人以上的房主会把放不下的装备记录换成一个短占位，再把记录另外发送。没有这个改动的机器会把占位当成数字来读，之后的每条记录都会错位，最后得到的错误玩家序号会不经检查地写进内存。2026-09-30 打的部分包自称 1.5.14，但其实没有拆分；而各版本 MultiSlot 共用同一类房间，所以版本号和房间都分辨不出这两种机器。现在每个玩家会在自己的大厅成员信息上发布一个标记（游戏本身从不读取这些信息）。房主只把拆分后的出击消息（以及另发的记录）发给看到过这个标记的成员。没有标记的成员得到的结果与 1.5.14 之前 EOS 的回应相同（消息不发出），日志在每个房间里记录他一次。**8 人以上的房间，所有人都要升级到 1.5.15 才能出击**，用 2026-10-01 整合包的人也一样。
- **出击消息先到时不再等重发：** 另发的记录是单独的包，可靠传输不保证它们之间的顺序，所以出击消息可能比记录先到。以前这时消息会被丢掉，游戏要等约 3 秒后的重发。现在消息会先暂存，记录一到就交给游戏，发送者、socket 和通道都保持原样。最多暂存 8 条（满了先丢最旧的），每条最多保留 30 秒，比游戏自己的重试时间更长。离开房间时清空。
- **扫描包更省：** 每个收发的游戏包都要查找占位。现在直接从一个候选字节跳到下一个，不再逐个位置去试。
- **日志：** `MISSION sync:` 行会记录：何时发布了我们的标记、哪个成员读不了拆分消息、暂存的消息何时交给游戏或被丢弃。

## 日本語

・分割した出撃データは、読める人にだけ送るようにしました：1.5.14 から、8人以上のホストは
  出撃データに入りきらない装備情報を短い目印に置き換え、本体は別に送っています。
  この変更が入っていない人のゲームは目印を数字として読み、それ以降の情報がすべてずれ、
  おかしなプレイヤー番号がそのままメモリーに書き込まれていました。2026-09-30 に作られた
  一部のパッケージは 1.5.14 と名乗っていても分割に対応しておらず、MultiSlot はどの版も
  同じ種類の部屋を使うため、版の番号や部屋では見分けられません。
  そこで各プレイヤーが、ゲーム本体は読まない「ロビーのメンバー情報」に目印を出すようにしました。
  ホストは、その目印が見えた人にだけ分割した出撃データ（と別送の情報）を送ります。
  目印がない人には 1.5.14 より前と同じく送られず、ログには部屋ごとに一度その人が記録されます。
  8人以上の部屋で出撃するには、全員が 1.5.15 にそろえてください（2026-10-01 のパックの人も含みます）。
・出撃データが先に届いても、再送を待たないようにしました：別送の情報とは届く順番が保証されない
  ため、以前は先に届いた出撃データを捨てて、約3秒後の再送を待っていました。今は一時的に預かり、
  情報がそろった時点でゲームに渡します（送り主・ソケット・チャンネルはそのままです）。
  預かるのは最大 8 件（あふれたら古いものから捨てます）、1 件につき最大 30 秒で、
  部屋を出ると消えます。
・すべての通信パケットに対する目印の検索を軽くしました。
・部屋の仕組みは変えていません。これまでどおり 1.5.5 以降の人とも互いに部屋が見え、参加できます。
